# 输出质量检查

每次调研报告交付前，主 agent 须按此清单自查。

## 强制检查项

### 1. 产出完整性

| 检查项 | 通过条件 |
|--------|---------|
| 调研计划文件存在 | `01_项目/调研/.plans/<slug>.md` 已写入 |
| 草稿文件存在 | `01_项目/调研/.drafts/<slug>-draft.md` 已写入 |
| 引用版草稿存在 | `01_项目/调研/.drafts/<slug>-cited.md` 已写入 |
| 最终报告存在 | `01_项目/调研/<YYYY-MM-DD>-<slug>.md` 已写入 |
| provenance 文件存在 | 末尾包含来源清单和验证状态 |

降级模式：如果某些步骤失败，最终报告仍须写入，并标注 `Verification: BLOCKED` 或 `PASS WITH NOTES`。

### 2. 引用完整性

| 检查项 | 通过条件 |
|--------|---------|
| 所有事实断言有 [^N] 标注 | 正文扫描无未标注的事实断言 |
| 无孤立引用 | 每个 [^N] 在参考文献列表中有对应条目 |
| 无孤立来源 | 参考文献列表中每条在正文被引用至少一次 |
| 无 [待验证] 残留 | 所有断言要么有引用，要么标注为 [主观判断] |

### 3. 事实准确性

| 检查项 | 通过条件 |
|--------|---------|
| 无编造的数据/案例 | 所有数值、案例有出处 |
| 无编造的引用 | 每条引用指向真实 URL |
| 推断已标注 | 推断性结论标注了 [推断] |

### 4. 审查结果

| 检查项 | 通过条件 |
|--------|---------|
| Reviewer 审查完成 | 有审查报告输出 |
| FATAL = 0 | 无事实错误 |
| MAJOR 已处理或在开放问题中说明 | 无被忽略的 MAJOR |

## 输出风险清单

调研报告常见的输出风险，写作和审查时须防范：

| 风险 | 描述 | 防范措施 |
|------|------|---------|
| 脚注堆砌 | 引用过多导致阅读体验差 | 核心断言引用 ≤3 个来源，支撑性引用合并 |
| 无来源断言 | 事实断言无引用 | Verifier 扫描移除 |
| 过度自信 | 证据不足但结论斩钉截铁 | 标注置信度、用「目前公开信息表明」等限定语 |
| 选择性引用 | 只引用支持结论的证据 | Reviewer 偏见检测 |
| 过时信息 | 引用已过时的数据 | 搜索时限定时间范围，标注信息时效 |
| 单一来源依赖 | 核心结论只依赖一个来源 | 标注 [单来源]，Reviewer 升级为 MAJOR |

## 自检命令

交付前主 agent 执行以下检查（逻辑层面的 checklist，不需要实际运行脚本）：

1. 打开最终报告，扫描所有 `[^` 引用标记，确认编号连续且在参考文献列表中有对应
2. 扫描所有数字（%、万、亿），确认每个有引用标注
3. 检查是否有「众所周知」「一般认为」等模糊表述，改为有引用或标注主观判断
4. 确认 provenance 清单的 Verification 字段不为空
5. 确认备选标题 ≥3 个
